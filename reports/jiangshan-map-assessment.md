## 结论摘要

| 问题 | 结论 |
| :--- | :--- |
| 数据本身能用吗 | **可以作为“教学情境锚点”，不能作为史实/边界底图直接入库。** 有 18 个时期、166 幅快照、3,454 个历史要素、536 条定点事件、104 位人物、7 条完整行迹；但边界是示意性的，数据无逐条出处，且没有独立诗词库。 |
| 许可证能放心用吗 | **不能按 MIT 放心用。** `LICENSE` 是 MIT，README 两版写 GPL-3.0，GitHub 侧栏按 LICENSE 显示 MIT；README 同时承认使用了 GPL-3.0 的 `aourednik/historical-basemaps`，并参考谭其骧《中国历史地图集》、CHGIS、Hartwell。**最保守应按 GPL-3.0 对待，且上游权利仍未清。** |
| 与 mneme 现有知识点匹配吗 | **主要匹配语文古诗文，不匹配历史。** mneme 没有历史 KU/题库，只有 11 册历史教材 PDF；语文 8,073 个 KU 中，保守口径可挂链约 **560 个（6.9%）**，古诗文/文言子集 **419/3,367（12.4%）**；名称直指的高置信批次 **153 个（1.9%）**。 |
| 推荐哪种接入 | **A 外链深链（有条件 GO）**。零复制、零 GPL 传染、工作量约 **2–2.5 人日**；B iframe 仅作可选实验；C 本地化部署/数据导入 **不建议**（GPL + 审图 + 数据格式三重成本）。 |
| 最大风险 | 许可证自相矛盾 + 上游数据权利不明 + 地图审图合规 + 示意边界被当成标准答案。 |
| 推荐动作 | 先做 **153 个高置信 KU** 的外链深链，统一加“第三方示意地图，非教材标准地图”标识；不复制任何 JS/几何/事件数据；法务与合规签字后再面向学生全量。 |

### 1.3 数据格式：不是 JSON/GeoJSON，而是 JS 内嵌 + 自定义压缩

| 文件 | 格式 | 能否直接 `JSON.parse` | 内容 |
| :--- | :--- | :--- | :--- |
| `js/map_data.js` | `window.DYNASTY_DATA = [ ... ];` | 可以（截取数组后） | 18 朝、165 阶段、442 大事、1,387 地名行 |
| `js/lore_data.js` | `window.ATLAS_LORE_DATA = { ... };` | 可以（截取对象后） | 536 事件、185 地名、104 人物、87 城市、20 关、7 行迹 |
| `js/atlas_snapshots.js` | IIFE + `const D = {"r":[...],"f":[...],"d":{...}}` | 不能直接解析 | 3,895 环、3,454 要素、166 快照，自定义 64 字符表 + VLQ 增量 + 坐标 /100 |
| `js/china_geo_data.js` | IIFE + VLQ | 不能 | 现代省界 |
| `js/i18n_dict.js` | `window.I18N_DICT` 类 JSON | 可以 | 中英词典 |
| `js/app.js` | 普通 JS | — | 应用逻辑、深链解析、`resolvePlace` |

**这意味着“数据导入”不是拷几个 JSON 文件**：几何需要按文件内 `dec()` 解码，要素通过索引引用环，快照通过索引引用要素；要转 GeoJSON/PostGIS 得自己写展开脚本并验证 166 个快照的引用完整性。

### 1.4 深链协议（这是最有价值的接入面）

仓库自带 AI-native 深链协议（`llms.txt` §1、`skills/jiangshan-atlas/SKILL.md`）：

| 参数 | 作用 | 示例 |
| :--- | :--- | :--- |
| `year` | 年份，可单值或逗号列表 | `?year=819`；`?year=1079,1080,1094,1097` |
| `place` | 古地名/今地名/英文/拼音；可单点或逗号路线 | `?year=819&place=蓝关`；`?year=763&place=剑外,巴峡,巫峡,襄阳,洛阳` |
| `person` | 人物档案/行迹 | `?person=sushi`、`?person=李白` |
| `journey` / `stop` | 指定 7 条行迹及站点 | `?journey=sushi&stop=7` |
| `hover` | 高亮某州/府/郡 | `?year=1102&place=浔阳&hover=江州` |
| `zoom` / `lng` / `lat` | 相机控制 | `?year=208&place=赤壁&zoom=2.6` |
| `lang` | 英文 UI | `&lang=en` |

深链解析在 `js/app.js`：`_restoreFromQuery()`（约 9560 行起）处理 `q/person/journey/year/trace`；`resolvePlace()`（约 8468 行起）按“名关 → 目标朝地名 → 地名志 → 其他朝地名 → 州府 → 现代省”顺序解析，所以 `蓝关`、`洛阳` 这类不在 `PLACE_GAZETTEER` 里的名字也能命中（通过事件点/地名行/州府）。

### 1.5 工程形态判断

- **优点**：零依赖、运行时零构建、静态可托管；深链协议完整；有 `atlasAPI.resolvePlace/inspect/locate` 浏览器 API；有 `llms.txt` 和 Agent Skill，适合 agent 生成链接。
- **缺点**：数据与展示强耦合；没有稳定的数据 API/JSON schema；几何是私有压缩格式；没有 per-datum `source` 字段；没有版本化数据契约；更新靠整体替换 JS。
- **对 mneme 的含义**：**适合“链接过去”，不适合“把数据拿过来”。**

## 二、许可证与合规

### 2.1 三处声明互相矛盾（已核实）

| 位置 | 声明 | 证据 |
| :--- | :--- | :--- |
| `LICENSE` 文件 | **MIT** | `LICENSE:1-3`，`Copyright (c) 2026 DeanChensj` |
| GitHub 侧栏 | **MIT** | GitHub API `license.spdx_id = "MIT"` |
| `README.md` | **GPL-3.0** | `README.md:168-175`，`License: GPL-3.0` |
| `README_ZH.md` | **GPL-3.0** | `README_ZH.md:171-176`，`开源协议：GPL-3.0` |
| `CONTRIBUTING.md` | 未声明许可证 | 仅贡献规范 |

补充证据：`LICENSE` 是在 **2026-10-09** 的提交 `9c8b7462`（`perf(geo): compress topology payloads ...`）里顺手加入的，新增 21 行 MIT；README 的 GPL-3.0 声明早于它。**这更像误加模板，而不是一次有意的双许可变更。** 但法律上 GitHub 侧栏和 `LICENSE` 都会显示 MIT，下游不能假装没看见。

**结论：不能把“MIT”当作可靠授权。** 对闭源商业产品，应按“**GPL-3.0 或更严**”做最保守假设，直到作者书面澄清。

### 2.2 上游数据源

README 自述（`README.md:170`）：

| 上游 | 许可证/权利状态 | 对本项目的影响 |
| :--- | :--- | :--- |
| `aourednik/historical-basemaps` | **GPL-3.0**（已核对其 LICENSE 为 GPLv3 全文） | 如果 `atlas_snapshots.js` 的世界政区几何派生自它，则该数据文件是 GPL 衍生作品，不能由 MIT 覆盖。 |
| 谭其骧主编《中国历史地图集》 | 正式出版物，**著作权保留**；无开源许可 | GPL 授权不能覆盖第三方地图作品；边界/注记/编绘成果的使用需授权。 |
| CHGIS（哈佛燕京/复旦） | 学术使用通常免费并要求引用；**商业再分发需核实条款** | 不能假定可随 MIT/GPL 一起商用。 |
| Robert M. Hartwell 历史 GIS | 学术数据集，条款需核实 | 同上。 |
| DataV GeoAtlas 现代省界 | 平台条款需核实 | 现代边界展示还涉及审图。 |

`atlas_snapshots.js` 中有 3,454 个要素、1,779 个唯一标题，包含“阿富汗、不丹、阿伊努、新罗、高句丽”等非中原政权，形态与 `historical-basemaps` 的世界政区数据高度一致。更直接的证据：在 `LICENSE` 加入之前的 `457ced0` 版本 README 里写的是 **“Derived from aourednik/historical-basemaps (GPL-3.0) with custom multi-phase historical refinements”**（`README.md:159`），当前版本才改成较含糊的“References”。结合这两点，**可以合理判断几何层使用了该 GPL 数据（至少部分）**。即使不作此判断，README 已经把 GPL-3.0 写进项目声明，下游不能忽略。

### 2.3 对 mneme 的约束矩阵

mneme 现状：仓库无 `LICENSE`，`docs/MONETIZATION.md` 定义了 FREE/PRO 商业化分层，属于**闭源商业产品**。因此：

| 使用方式 | 是否复制代码/数据 | GPL-3.0 是否触发 | 闭源商用可行性 | 主要风险 | 建议 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **A. 纯外链**（新标签打开作者站点） | 否 | 通常否（不构成复制/衍生/分发） | 可行 | 可用性、内容漂移、学生跳出、地图合规 | **推荐** |
| **B. iframe 指向作者站点** | 否（浏览器加载作者副本） | 通常否 | 可行 | 第三方可用性、无 `postMessage`、移动端性能、合规 | 可选，feature flag |
| **C1. 自托管静态站** | 是（复制 HTML/JS/数据） | **是** | 需以 GPL-3.0 发布对应源码，与闭源 PRO 冲突 | GPL + 上游权利 + 审图 + 维护 | 不建议 |
| **C2. 抽数据入库** | 是（复制/改编几何、事件、地名） | **是** | 需 GPL + 上游授权 | 数据权利、格式解码、长期维护 | 不建议 |
| **D. 只手工摘录少量事实**（年、地名、人物名） | 事实层面低 | 可能不触发 | 低–中 | 事实不受版权，但成批坐标/汇编仍可能受保护；仍要署名 | 谨慎，逐条标注 |

要点：

1. **MIT 与 GPL 的单向兼容**：MIT 代码可以被并入 GPL 作品，但 GPL 数据不能反向被 MIT 覆盖。作者可以把“代码”MIT、“数据”GPL，但当前仓库没有做这种拆分，几何和事件都在同一批 JS 里。
2. **GPLv3 没有 AGPL 的网络条款**：如果完全内部使用、不向浏览器分发，义务不触发；但 mneme 是面向学生的公网 Web 产品，把 JS 发给浏览器通常构成分发。**公网自托管 = 要按 GPL 处理。**
3. **上游权利不会因为作者写了 GPL 就变干净**：谭其骧图集、CHGIS、Hartwell、DataV 的权利需要单独尽调。即使 mneme 愿意 GPL，也不能自动获得这些授权。
4. **地图合规是独立风险**：项目未见审图号（`grep 审图` 为空）。面向未成年人产品公开展示中国历史/现代边界，涉及《地图管理条例》下的地图审核与“问题地图”风险；历史边界示意图与现代省界混用，风险更高。外链把展示责任留在作者站点，风险相对低；iframe/自托管会把展示带进 mneme 的产品界面。

### 2.4 许可证结论

- **只做外链/iframe**：不复制，GPL 传染风险最低；仍要做“第三方内容”标识与合规评估。
- **复制数据/自托管**：必须按 GPL-3.0 开源对应部分，且不能解决谭其骧/CHGIS 的上游权利；对闭源商业 mneme **不建议**。
- **如果未来真要做本地化**：先让作者书面澄清 LICENSE（MIT 还是 GPL）、确认 `historical-basemaps` 的使用范围与派生关系、取得谭其骧/CHGIS/DataV 的商用授权，再做审图。没有这三步，不要动工。

## 三、与 mneme 现有知识点对照

### 3.1 mneme 有没有历史学科数据？

**没有历史 KU/题库。**

| 检查项 | 结果 |
| :--- | :--- |
| `data/ku_packages/` 68 个包 | 学科只有 `chinese`（8,073 KU）、`math`（2,409）、`physics`（1,571）、`english`（21）；**无 history** |
| `data/kp_compare/` | 只有 `数学/物理/英语/语文` 四个目录；**无历史** |
| `data/seed_questions.json` | 只有广东数学等题目；无历史题 |
| 历史教材 PDF | `curriculum_standards/` 有 **11 册**：中国历史七上/七下/八上/八下、世界历史九上/九下、高中中外历史纲要上/下、选择性必修 1/2/3 |
| 历史相关产品位 | `services/related_labs.py:560-580` 有 `history` 学科的“著名战役沙盘 · WarTable”，关键词含长平、巨鹿、官渡、赤壁、淝水 |

所以：**历史目前只是“教材 PDF + 一个战役实验室入口”，没有 KU、没有考点、没有题目、没有掌握度链路。** 地图的历史价值现在只能落在语文古诗文和跨学科拓展上；要形成历史学科的闭环，得先建历史 KU/题库，这是另一个项目。

### 3.2 可挂链判定方法

1. 从 jiangshan 抽取锚点白名单：
   - `gazetteerPinyin` 的 112 个诗境/地名键（赤壁、桃花源、泰山、岳阳楼、蓝关、黄州、零丁洋、京口、三峡、潼关、轮台、楼兰、玉门、阳关、阴山……）；
   - 20 个名关；
   - 7 条完整行迹人物（秦始皇、张骞、诸葛亮、玄奘、李白、苏轼、王阳明）。
2. 对 mneme 语文 8,073 个 KU 的 `name + description + source_excerpt + rich_content` 做全文匹配。
3. 分别统计“正文命中”和“名称直指”（锚点出现在 KU 名称里，置信度更高）。
4. 用 `ku_type in {shici_jianshang, mingju, mingpian, wenyan_word, wenyan_syntax, wenyan_yuedu, mingzhu_yuedu}` 定义“古诗文/文言”子集（3,367 KU）。

> 这是**机械可挂链**上限，不等于“每个都值得挂”。真正上线建议先做名称直指的高置信批次。

- 语文侧真正“年 + 地 + 诗”三要素齐全、挂上去不牵强的，是 **韩愈蓝关、文天祥零丁洋、辛弃疾京口、苏轼黄州、杜甫归乡路线、岳阳楼、三峡** 这一类。
- 赤壁数量最大，但**最容易挂错**：杜牧《赤壁》是 208 年蒲圻古战场；苏轼《赤壁赋》《念奴娇》是 1082 年黄州文赤壁；《核舟记》是“大苏泛赤壁”的文学场景。必须按 KU 分别配置，不能一个 `place=赤壁` 打天下。
- 长平、张骞、玄奘在语文 KU 里几乎为零，说明**地图的历史价值目前无法通过语文 KU 兑现**；它们更适合放进 `related_labs` 的 WarTable 或未来的历史学科。

### 3.5 对照结论

1. **可挂链数量**：保守 560 个（6.9% 语文 KU），高置信 153 个（1.9%），放宽 818 个（10.1%）。
2. **覆盖率**：古诗文/文言子集 12.4%–16.8%，是合理的“情境增强”比例；不适合全量语文 KU。
3. **历史学科**：0 个可挂 KU，因为 mneme 还没有历史 KU；这是产品缺口，不是地图的问题。
4. **最快见效**：`related_labs` 的 5 个中国战役（长平、巨鹿、官渡、赤壁、淝水）**5/5 都能挂**，且不需要等历史 KU 建设。

## 四、帮助学生理解的评估

### 4.1 教学价值

| 维度 | 价值 | 适用场景 |
| :--- | :--- | :--- |
| 时空概念 | 把“朝代”变成可拖动的时间轴与版图变化；学生能看到“安史之乱前后疆域/政区”的差异 | 历史入门、语文背景介绍 |
| 古今地名 | 点地溯源卡片展示同一地点从战国郡县到唐道、宋路、元明清行省、现代省市的沿革 | “这首诗写的是哪里”“左迁到哪里” |
| 人物行迹 | 7 条完整路线 + 68 站，支持多年份路线 URL；适合贬谪、出使、北伐、壮游 | 苏轼、杜甫、韩愈、文天祥、李白、张骞、玄奘、诸葛亮、王阳明 |
| 事件地理 | 战场、关隘、河流、地形同屏；能解释“为什么是这里” | 长平、赤壁、淝水、官渡、巨鹿 |
| 多模态 | 地图 + 引文 + 年号 + 中英双语；比纯文字更容易建立空间感 | 课堂演示、复习情境 |

**最值得做的三个教学动作：**

1. **诗境定位**：在 KU 详情页放“在地图上看看”，点开是“819 年 · 蓝关”，学生一眼看到秦岭、蓝田、长安到潮州的方向。
2. **路线叙事**：杜甫 763 归乡路线、苏轼 1079–1097 贬谪路线，用多站点 URL 直接画出弧线；比单点更有“过程感”。
3. **战役沙盘**：长平/赤壁/淝水挂到 WarTable，先看地形再看胜负，避免把战争背成“年份+人名”。

### 4.2 适用边界

- **它是“情境锚点”，不是“标准答案”**：边界是示意性的，不能用来判分、不能替代教材地图。
- **文学地点 ≠ 历史地点**：赤壁（文/武）、江州（秦汉重庆/唐宋九江）、隆中（襄阳）与南阳（教材注释）都存在争议或同名异地。
- **年份粒度是“年”**：诗作、事件的具体月日不覆盖；路线年份有时是“代表年”。
- **没有逐条出处**：536 条事件、185 个地名没有 `source` 字段；不能当作学术引用。
- **没有历史 KU**：无法对齐历史课标/考点，也无法进入掌握度链路。

### 4.3 准确性风险

| 风险 | 说明 | 缓解 |
| :--- | :--- | :--- |
| 示意边界 | 项目自己声明“schematic approximations”；不是测绘边界 | UI 明示“示意”；不用于考试/边界题 |
| 同一地物多套坐标 | 赤壁有 113.95/29.95、113.90/29.88、113.901/29.721 三套，最北最南差约 26 km（地名志与地名行之间约 18 km） | 只用“朝代表 + 地名”做锚点，不展示精确坐标 |
| 年份争议 | 玄奘出发 627 vs 629；李白出生地碎叶说 vs 蜀中说 | 标注“据教材/一说”；避免出判断题 |
| 标签合并 | 苏轼“1077 徐州·湖州”把徐州抗洪与 1079 乌台诗案并在一站；诸葛亮“柴桑·赤壁”把 九江柴桑与蒲圻赤壁并在一站 | 拆成两站或改写文案 |
| 同名异地 | 江州（重庆/九江）、赤壁（黄州/蒲圻）、隆中（襄阳/南阳） | 深链必须带 `year`，必要时带 `hover` |
| 事实错误 | 王阳明 1492 “进士及第”（实际 1499） | 修正或避开该站 |
| 地图合规 | 无审图号；历史边界与现代边界混用 | 外链 + 免责声明；本地化前做审图 |

### 4.5 使用规范建议

1. 所有入口显示：**“第三方示意地图，非教材标准地图；边界与坐标仅供情境参考”**。
2. 链接必须带 `year`；跨时代的同名地点（江州、赤壁）必须带 `year`，必要时带 `hover`。
3. 赤壁严格拆分：杜牧 208 蒲圻；苏轼 1082 黄州；核舟记按课文情境另配。
4. 玄奘/西游记、李白出生地、隆中/南阳：写成“据教材/一说”，不出唯一答案题。
5. 不把地图截图作为题目材料；不基于地图边界出题。
6. 外链新标签打开，带 `rel="noopener noreferrer"`；不把学生 ID 拼进 URL。

## 五、接入方案对比

### 5.1 三种方案

| 维度 | A. 外链深链 | B. iframe 嵌入 | C. 本地化部署 + 数据导入 |
| :--- | :--- | :--- | :--- |
| 是否复制代码/数据 | 否 | 否（指向作者站点） | 是 |
| GPL 风险 | 最低 | 低（不复制） | **高**（分发/衍生） |
| 上游权利风险 | 低（不复制） | 低–中（展示第三方内容） | **高**（谭其骧/CHGIS/DataV） |
| 地图审图 | 展示责任在作者站点 | 展示进入 mneme 界面，需评估 | **必须审图** |
| 工作量 | **2–2.5 人日** | 3.5–5 人日 + 1–2 人日合规 | **10–15 人日 + 3–5 人日法务 + 长期维护** |
| 体验 | 跳出新标签；简单可靠 | 留在产品内；可嵌详情弹窗 | 完全可控；可离线/内网 |

### 5.2 A 方案：外链深链（推荐）

**设计**

1. 不把 URL 硬编码进 `rich_content`。新增旁路表（推荐）：

```sql
-- 仅示意，不落地到本次只读评估
ku_external_map_links (
  ku_id            text primary key references knowledge_units(id),
  provider         text not null default 'jiangshan',
  anchor_type      text not null,      -- place | route | person | event
  anchor_year      int,               -- 单点年；路线为 null
  anchor_place     text,               -- 单点地名；路线为逗号分隔
  anchor_person    text,
  confidence       text not null,      -- high | medium
  label            text,               -- “在地图上看看”
  created_at       timestamptz not null default now()
);
```

2. 后端只存“锚点”，URL 由服务端/前端统一拼：

```text
https://deanchen.me/jiangshan-map/?year={year}&place={encodeURIComponent(place)}
https://deanchen.me/jiangshan-map/?person={person}
https://deanchen.me/jiangshan-map/?year={y1,y2,...}&place={p1,p2,...}
```

3. 前端在 KU 详情/讲解卡片底部渲染按钮：`在地图上看看 ↗`，`target="_blank"`，`rel="noopener noreferrer"`；移动端同样新标签。
4. 只对 `confidence=high` 的 153 个 KU 开放；灰度开关 + 一键下线。
5. 加 UTM（不含 PII）：`&utm_source=mneme&utm_medium=ku&utm_campaign=map_link`。注意：加 UTM 会改变作者页面的 canonical/分享行为，需确认不违反对方预期；也可不加 UTM，改用自家点击埋点。

**实施步骤与工作量**

| 步骤 | 内容 | 人日 |
| :--- | :--- | ---: |
| 1 | 从 153 个名称直指 KU 生成锚点 CSV，人工复核（重点赤壁/江州/隆中/玄奘） | 0.5–1.0 |
| 2 | 旁路表 migration + 只读 API/序列化字段 | 0.5 |
| 3 | KU 详情页按钮 + 空值/失败兜底 + 新标签 | 0.5 |
| 4 | 20 条链接 QA（桌面/移动/中文编码/负年份）+ 免责声明 | 0.5 |
| **合计** | | **2.0–2.5** |

**验收标准**

- 20/20 抽查链接打开后年份、地名正确；赤壁按“杜牧 208 / 苏轼 1082 黄州”分别验证。
- 未配置锚点的 KU 不显示按钮；不改变现有布局与练习流程。
- URL 不含学生 ID、手机号、学校等 PII。
- 所有按钮可见“第三方示意”说明；开关可一键关闭。
- 外链失败（超时/404）有文案兜底，不阻塞答题。

**风险与缓解**

| 风险 | 缓解 |
| :--- | :--- |
| 站点不可用/大陆访问慢 | 按钮不阻塞主流程；失败兜底；监控点击后跳出率 |
| 内容漂移/作者改版 | 只存锚点不存全文；定期抽检；版本号记录 |
| 学生跳出产品 | 新标签 + 明确“第三方”；课堂场景由教师控制；不做自动跳转 |
| 地图合规 | 法务评估；UI 明示“非标准地图”；不截图进题目 |
| 许可证 | 不复制；保留作者署名与仓库链接；如作者要求，停止外链 |

### 5.3 B 方案：iframe 嵌入（可选实验）

**技术事实**

- 线上 `https://deanchen.me/jiangshan-map/` 返回 `HTTP/2 200`，响应头**没有** `X-Frame-Options` 或 `CSP frame-ancestors`，技术上可被 iframe。
- 但页面**没有跨域 `postMessage` 协议**；`window.atlasAPI` 只在同源 iframe 内部可用。父页面只能通过改 `iframe.src` 传参，读不到当前年份/地点，也收不到点击事件。
- 首屏要加载约 1.05 MB gzip 的核心 JS + 0.8 MB 地形 + 字体；移动端 WebView 里可能明显卡顿。
- 需要给 mneme 加 `frame-src https://deanchen.me`（或 `frame-src *`，不推荐）。

**适用**

- 只读“探索”模式：一个可关闭的抽屉/弹窗，默认加载某个 KU 的深链，用户可继续在 iframe 内操作。
- 不作为答题、判分、必达链路的组成部分。

**工作量**：3.5–5 人日（容器 1–1.5、CSP/安全 0.5、加载/错误/移动端 1–1.5、QA 0.5–1）+ 合规评审 1–2 人日。

**结论**：可以做小流量实验，但不建议作为主方案；没有 `postMessage` 意味着无法做“点地图回填 KU 状态”的深度联动。

### 5.4 C 方案：本地化部署 + 数据导入（不建议）

**C1 自托管静态站**

- 复制 20.8 MB 工作树（可裁掉 16 MB 演示图，保留 3–5 MB 运行时）到 Nginx/对象存储；无构建步骤。
- 工作量 1.5–2.5 人日（子路径、缓存、压缩、监控、回滚）。
- **GPL-3.0 触发**：需要以 GPL-3.0 提供对应源码（含修改），与闭源 PRO 冲突；还要处理上游权利与审图。
- 更新靠整体替换，缺少版本化数据契约。

**C2 数据导入**

- 几何是自定义 VLQ + 环索引 + 快照索引；要先写解码/展开脚本，再转 GeoJSON/PostGIS，再做 API。
- 3,895 环 / 3,454 要素 / 166 快照，展开后数据量会显著增大；还要处理跨快照重复、坐标系、简化精度。
- 5–8 人日只是“能跑”，不含内容校对、审图、长期维护。
- 事件/地名/人物可以单独抽，但同样受 GPL 与上游权利约束；且没有 per-datum source，教学可信度不足。

**总计**：10–15 人日工程 + 3–5 人日法务/合规 + 每季度 1–2 人日维护。**除非历史成为 mneme 的一等学科、且法务确认 GPL/上游/审图全部可行，否则不做。**

### 5.5 推荐路线

**结论：A（有条件 GO）；B 仅实验；C NO-GO。**

分阶段：

| 阶段 | 动作 | 时间 | 退出条件 |
| :--- | :--- | :--- | :--- |
| Phase 0 | 法务/合规确认“外链第三方地图”的政策；准备免责声明；向作者发一封许可证澄清邮件（MIT vs GPL，是否允许教育产品外链/引用） | 0.5–1 人日 | 书面/邮件回复或内部风险接受 |
| Phase 1 | 153 个高置信 KU 锚点 + 旁路表 + 按钮 + 20 条 QA | 2–2.5 人日 | 20/20 链接正确；无布局回归；开关可用 |
